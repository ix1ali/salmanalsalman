# نظام إدارة عقار سلمان السلمان

تطبيق ويب عربي (RTL) بالكامل لإدارة العمارات والشقق والمستأجرين والعقود والإيجارات،
مصمَّم أساسًا للاستخدام على الجوال. يعمل حاليًا **بدون أي خادم** — كل البيانات محفوظة
داخل المتصفح — وجاهز للربط بـ Supabase عند الحاجة.

---

## التشغيل

```bash
npm install
npm run dev
```

ثم افتح <http://localhost:3000>.

### حسابات الدخول التجريبية

| الدور | اسم المستخدم | كلمة المرور | الصلاحيات |
|---|---|---|---|
| مدير | `admin` | `Admin@1234` | كل شيء |
| مشاهد | `viewer` | `Viewer@1234` | اطلاع وتقارير فقط، بدون تعديل |
| حارس | `guard` | `Guard@1234` | الشقق والبلاغات، بدون بيانات مالية |

> غيّر كلمات المرور من **الإعدادات ← كلمة المرور** قبل أي استخدام حقيقي.

## الأقسام

| الصفحة | المسار | المحتوى |
|---|---|---|
| الرئيسية | `/` | كم شقة مؤجرة وكم فاضية، إيجار الشهر، تنبيهات، ومَن لم يدفع |
| الشقق | `/apartments` | قائمة الأدوار — اضغط الدور تنفتح شققه: الرقم، المستأجر، الإيجار، بحدّ ملوّن حسب الحالة |
| المستأجرون | `/tenants` | البيانات، السجل المالي، المستندات، اتصال وواتساب |
| الإيجارات | `/finances` | كشف الشهر: مين دفع ومين ما دفع + تسجيل الدفعة بضغطة، والمصاريف والمتأخرات |
| الطباعة | `/print` | **كل الطباعة في مكان واحد**: عقد الإيجار، وصل الاستلام، الكشف الشهري، كشف حساب مستأجر، سجل المستأجرين، طلب الإخلاء |
| التنبيهات | `/flags` | الشقق المعلّمة بتحذير وسببه، وزر «تم الحل» |
| المستندات | `/documents` | كل الملفات المرفوعة مع تنبيه انتهاء الصلاحية |
| المراسلات | `/memos` | ملاحظات وإعلانات داخلية بين المستخدمين — عنوان ونص، الأحدث أولًا |
| العمارات | `/buildings` | إضافة/تعديل/حذف عمارة، وإدارة الأدوار |
| المستخدمون | `/users` | الحسابات والصلاحيات وسجل العمليات (للمدير) |
| الإعدادات | `/settings` | اسم الجهة، كلمة المرور، النسخ الاحتياطي |

> كل ما يخص شقة معيّنة (المستأجر، العقد، الإيجار، التنبيه، المستندات، الطباعة)
> موجود داخل بطاقة الشقة نفسها — تضغط الشقة ويفتح كل شيء.

### البيانات

بيانات النظام مستوردة من سجل المكتب الفعلي (`برنامج ادارة عقار تراب.accdb`):

- **عمارة تراب** — حولي الجنوبي، قطعة 10، شارع موسى بن نصير، قسيمة 21/79، عمارة رقم 37.
- **٩٢ وحدة**: ٩٠ شقة (الأرضي ٨، الأول–السادس ١٢ لكل دور، السابع ١٠) + المحل + السرداب.
- **٥٩ مستأجرًا** بأسمائهم وأرقامهم المدنية وجنسياتهم ومهنهم وهواتفهم وقيم إيجاراتهم ومدد عقودهم.

ما نُظّف عند الاستيراد (دون تغيير أي قيمة جوهرية): توحيد أسماء الأدوار، ونسبة كل وحدة إلى
دورها من أول رقمها، وتوحيد كتابة الجنسيات. والسجلات الناقصة أو التي بها تعارض في التواريخ
وُضعت عليها **ملاحظة تنبيه حمراء** لمراجعتها — تجدها في صفحة «التنبيهات».

لا تُختلق أي بيانات مالية: سجل المكتب لا يحوي دفعات، فيبدأ النظام بسجل تحصيل فارغ،
وتُحتسب المتأخرات ابتداءً من الشهر المحدَّد في **الإعدادات ← بداية احتساب المتأخرات**.

## الأمان

- كلمات المرور مشفّرة بـ **PBKDF2-SHA256** بـ ١٥٠ ألف دورة وملح عشوائي لكل مستخدم — لا تُخزَّن أبدًا كنص صريح.
- **إيقاف مؤقت** ٩٠ ثانية بعد ٥ محاولات دخول فاشلة.
- **خروج تلقائي** بعد ٢٠ دقيقة خمول، وانتهاء إجباري للجلسة بعد المدة المحددة في الإعدادات.
- تغيير كلمة المرور يُبطل الجلسات القديمة فورًا.
- كل صفحة محمية بحارس مصادقة، وكل زر تعديل محكوم بصلاحية من `permissions.ts`.
- **سجل عمليات** لكل إضافة/تعديل/حذف (المستخدمون ← السجل).

> ملاحظة مهمة: ما دام التطبيق يعمل بدون خادم، فالحماية على مستوى الواجهة. الحماية الحقيقية
> تأتي مع Supabase عبر سياسات RLS الموجودة في `supabase/schema.sql`.

## الربط بـ Supabase

1. أنشئ مشروعًا على [supabase.com](https://supabase.com).
2. شغّل `supabase/schema.sql` في **SQL Editor** — ينشئ الجداول والفهارس وسياسات RLS و bucket المستندات.
3. أنشئ مستخدمًا من **Authentication → Users**، ثم أضف صفّه في `profiles` بدور `admin`
   (الأمر جاهز في آخر ملف الـ SQL).
4. أضف ملف `.env.local`:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=xxxx
```

5. ثبّت العميل واستبدل طبقة التخزين:

```bash
npm install @supabase/supabase-js
```

كل القراءة والكتابة تمر عبر `src/lib/store.tsx` (`data` للقراءة و`update()` للكتابة)،
و`src/lib/auth.tsx` للمصادقة. استبدل هذين الملفين باستدعاءات Supabase وسيعمل باقي
التطبيق كما هو — الصفحات لا تعرف شيئًا عن مصدر البيانات.

أسماء الحقول في SQL بصيغة `snake_case` بينما الواجهة `camelCase`، فحوّلها في طبقة
التخزين فقط (أو استخدم `.select()` مع تسميات مستعارة).

## النماذج المطبوعة

كل نموذج منقول عن أصله المعتمد لدى المكتب ويُعبَّأ تلقائيًا:

| النموذج | الأصل | المحتوى |
|---|---|---|
| **عقد إيجار** | `rent1.docm` | الترويسة بالعربية والإنجليزية، الطرفان، وصف العين، ثم البنود التسعة عشر كاملة |
| **وصل استلام** | حقول سجل المكتب | مبلغ وقدره / دينار / فلس، المبلغ كتابةً، نقدًا أو شيك رقم، على بنك، عن شهر |
| **طلب إخلاء** | `طلب اخلا.doc` | إقرار الإخلاء وتسليم العين وبراءة الذمة من وزارة الكهرباء والماء |
| **الكشف المالي الشهري** | جديد | المقبوضات والمصروفات وصافي الدخل ونسبة التحصيل |
| **كشف حساب مستأجر** | جديد | كل ما سدّده المستأجر وما تبقى عليه |
| **سجل المستأجرين** | بديل جدول Access | جميع الوحدات المؤجرة وبيانات مستأجريها في جدول واحد |

قيم الغرامة الإدارية وأجرة المشرف الفني ويوم الاستحقاق تُقرأ من **الإعدادات**، فتتغير في
كل العقود دفعة واحدة.

## الأرقام والمبالغ

كل مبلغ مالي في النظام يمر عبر مكوّن واحد (`Money`) فيظهر دائمًا مصحوبًا بـ **د.ك**،
وبثلاث خانات عشرية. الأرقام المجرّدة (عدد الشقق، عدد الأشهر، نسبة الإشغال) تظهر بلا لاحقة،
فيسهل التمييز بينها وبين المبالغ من النظرة الأولى.

الخط **IBM Plex Sans Arabic** بعائلة واحدة وأوزان متعددة، وسلّم مقاسات ثابت
(`t-display` / `t-title` / `t-section` / `t-body` / `t-sm` / `t-xs`).
البطاقات بحدّ رفيع بلا ظل، والكثافة عالية عمدًا: هذه أداة عمل يومي لا لوحة عرض.

كل القيم في مكان واحد: `src/app/globals.css`، وألوان حالة الوحدة في `src/lib/unitColor.ts`.
